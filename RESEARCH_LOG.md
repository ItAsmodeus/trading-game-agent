### H-006: Log-Normal Z-Score Features
**Источник:** Анализ master bot (Quantum Leap v1, коммит eb49679, 2026-05-18)
**Идея:** Добавить в observation 4 новых признака на каждый бар в LOOKBACK окне:
- `mu_60` — натуральный дрифт (60-bar log return drift) — насколько сильна инерция
- `sigma_20` — 20-bar аннуализированная волатильность (для 1h: ×√8760)
- `z_score_ln` — Z-score от "справедливой" цены по GBM: z=(price−expected)/(σ×price/√8760)
- `regime` — отклонение цены от MA200 (clip ±50%)
**Разница от main bot:** Они используют hardcoded пороги в rule-based TradeAnalyzer (z<-1.5 → BUY). Мы подаём сырые числа агенту и даём PPO самому выучить пороги — это гибче.
**Ожидание:** Агент будет "видеть" перекупленность/перепроданность через GBM модель, а не только RSI/MACD.
**Статус:** ✅ Реализовано в data_loader.py — войдёт в v5
**Метрика успеха:** WF Sharpe > v4 baseline, avg_trade_bars увеличивается (агент дольше держит позиции)

### H-008: Soft Stop-Loss via Reward Shaping (v5)
**Источник:** Сравнение с main bot (DIARY.md, 2026-05-19) — их stop-loss -3% на сделку обрезает катастрофы
**Идея:** Не хардкодить стоп-цену, а добавить per-bar penalty когда позиция в минусе >5%:
```python
excess = abs(unrealized_pct) - SOFT_STOP_PCT  # глубина убытка сверх 5%
pnl += -SOFT_STOP_SCALE * excess              # -0.002 × excess (линейный)
```
Агент сам выучит когда закрывать позицию — без фиксированного порога как у main bot.
**Разница от main bot:** Их -3% срабатывает всегда. Наш штраф растёт пропорционально глубине — агент балансирует "терпеть просадку vs закрыть".
**Разница от старого DD penalty:** Тот был portfolio-level quadratic → 0 trades. Этот position-level linear → только убыточные позиции.
**Статус:** ✅ Реализовано для v5 (SOFT_STOP_PCT=0.05, SOFT_STOP_SCALE=0.002)
**Метрика успеха:** Avg DD в плохих окнах < 8% (v4 окна 15-16: 14-18%)

### H-007: Anti-Panic-Trading (v5)
**Источник:** Диагностика v4 (2026-05-19)
**Идея:** В v4 агент совершал 489 сделок/месяц в убыточных окнах × ~0.07% комиссии = ~34% потерь на fees. Причины:
1. Milestones `trades_50` и `trades_100` **поощряли** оверторговлю (+0.03/+0.05 бонус)
2. Churn penalty: bars<5 → -0.001 — агент просто держал ровно 5 баров, потом флипал
**Решение (реализовано):**
- Удалены milestones `trades_50`, `trades_100`; `trades_10` уменьшен до 0.005
- CHURN_BARS: 5→10, CHURN_PENALTY: -0.001→-0.003
- Все capital milestone бонусы урезаны ~40% (мотивация к риску была слишком высокой)
- Survival milestone бонусы увеличены (reward за сохранение капитала)
**Статус:** ✅ Реализовано для v5
**Метрика успеха:** Avg trades/window < 200 (в v4: 289 в плохих окнах)

### H-010: SHORT/COVER capability — двусторонняя торговля (v7)
**Источник:** Диагностика v6 walk-forward (2026-05-19) — окна 16/17 (2024-07 — 2025-04) дают -7.33% и -8.67% на медвежьем рынке BTC 2025
**Идея:** Расширить action space с 7 до 13: добавить SHORT 25/50/100% (открыть/добавить короткую позицию) и COVER 25/50/100% (закрыть часть/всё шорта). Агент сможет зарабатывать на падении, а не просто сидеть в кэше.
**Реализация:**
- `market_sim.py`: `short()` — маржинальная торговля (cash -= margin), `cover()` — cash += margin + PnL
- `trading_env.py`: signed `position_ratio` в obs (отрицательный = шорт), +6 действий в ACTION_MAP
- `config.py`: N_ACTIONS: 7→13, SIGMA_IDLE_EXEMPT=1.2 (волатильный фильтр idle penalty)
**Разница от main bot:** У них тоже есть SHORT в action space, но нет signed position_ratio в obs. Наш агент явно "видит" что он в шорте и какой % капитала занято.
**Ожидание:** Окна 16/17 (медвежий 2025) дадут положительный return вместо -7% / -8%
**Статус:** ✅ Реализовано (v7), smoke test пройден. Запуск — после финала v6.
**Метрика успеха:** WF Sharpe v7 > v6; особенно окна медвежьего рынка

### H-012: Self-Play Training — агент соревнуется с собственной прошлой версией (v9)
**Источник:** AlphaGo / OpenAI Five подход
**Идея:** `SelfPlayTradingEnv` — на каждом шаге рядом торгует замороженная копия предыдущего окна.
Reward = 70% собственный PnL + 30% (свой_портфель − портфель_соперника) / 10k.
**Статус:** ❌ ОТКЛОНЕНО (2026-05-25). WF Sharpe -0.263 (регресс с v7 +0.379)
**Причина провала:** Неправильная формулировка задачи. Оба агента торгуют независимо на одних данных — нет реальной петли обратной связи. Competitive signal (30%) просто добавлял шум к reward. В AlphaGo оппонент ГЕНЕРИРУЕТ сложные позиции для тебя. В трейдинге "оппонент" должен генерировать сложные рыночные условия — не торговать рядом.
**Что сохранили:** Понимание: правильный self-play для трейдинга = adversarial режим-селектор (→ H-014)

### H-013: Liquidation Cascade Proxy (v10)
**Источник:** Анализ рыночной микроструктуры
**Идея:** `liq_signal` (знаковый: лонги/шорты ликвидированы) + `liq_recent` (память за 3 бара). Принудительные ликвидации = каузальный сигнал, не лаг-индикатор.
**Статус:** ⚠️ ЧАСТИЧНЫЙ УСПЕХ (2026-05-25). WF Sharpe -0.383 (хуже v7 +0.379).
**Причина:** 15m таймфрейм + alpha reward вместе дали противоречие: alpha reward = агент vs BTC buy-and-hold → агент сидит в кэше в bull market = плохо. В медвежьих окнах улучшение (2022: -19%→-3.5%), в бычьих — ухудшение.
**Что сохранили:** `liq_signal` / `liq_recent` остаются в obs. 15m остаётся. Alpha reward — под вопросом.

### H-014: Adversarial Regime Training (v11)
**Источник:** AlphaGo minimax — правильная интерпретация self-play для трейдинга
**Идея:** Вместо "агент vs агент" → "агент vs режим-селектор". `RegimeAdversary` (Thompson Sampling бандит) выбирает сегменты данных (bull/bear/sideways/volatile). Adversary "побеждает" когда агент теряет деньги в этом режиме → с временем фокусируется на самых сложных режимах.
**Ключевое отличие от H-012:** Adversary генерирует УСЛОВИЯ (какой рыночный режим агент видит), а не торгует рядом. Это прямая аналогия AlphaGo: оппонент создаёт сложные позиции, а не копирует твои ходы.
**Реализация:** `env/adversarial_env.py` — `classify_segments()` + `RegimeAdversary` + `AdversarialRegimeEnv`. Сегменты по 1440 баров (2 недели), классификация по `regime` + `sigma_20` колонкам с квантильными порогами.
**Статус:** 🔄 Обучается (2026-05-25). 7/23 окон завершено.
**Промежуточные результаты:** Окна 1-3 (adversary холодный) хуже — ожидаемо. Окна 4-7 (adversary накопил статистику): +3.6% / +6.0% / -2.8% / -0.7% — заметное улучшение по сравнению с v10.
**Метрика успеха:** WF Sharpe > v7 (+0.379), в идеале > 0.7
